### Bug ID: BUG-001
**Title:** Форма входу: відсутнє блокування облікового запису на 15 хв після 3 невдалих спроб введення пароля (F-10, S-20)  
**Severity:** Minor  
**Priority:** P3  
**Linked:** test case TC-002; requirement F-10, S-20, GUI-10  
**Reporter:** Олександр Пархоменко (Інженер з тестування)  
**Reviewer:** Олександр Панайотов (Скрам-майстер / Рецензент) | **Дата рецензування:** 22.10.2026 | **Статус:** Reviewed ✓  

#### Description
Вимога F-10 (узгоджена з системною вимогою безпеки S-20 у виправленій специфікації SRS 1.1) встановлює: «Після 3 невдалих спроб входу поспіль обліковий запис блокується на 15 хвилин; користувач бачить повідомлення про блокування».  
Фактично на demo-стенді `sandbox.moodledemo.net` після трьох підряд некоректних спроб введення пароля блокування облікового запису не активується: система лише оновлює стандартне повідомлення про помилку та дозволяє необмежений перебір паролів.  
*Обґрунтування Severity:* Рівень Minor обрано тому, що дефект не перешкоджає автентифікації користувачів із валідними даними та не порушує базовий функціонал системи, проте становить незначне відхилення від політики захисту.  
*Обґрунтування Priority:* Пріоритет P3 призначено, оскільки відсутність блокування не заважає виконанню подальших тест-кейсів у тестовому середовищі.

#### Steps to reproduce
1. Відкрити браузер Google Chrome (чиста сесія інкогніто).
2. Перейти за адресою `https://sandbox.moodledemo.net/login/index.php`.
3. У поле «Username» ввести `student`.
4. У поле «Password» ввести невірний пароль `wrong_pass_1` та натиснути «Log in».
5. Повторно ввести невірний пароль `wrong_pass_2` та натиснути «Log in».
6. Втретє ввести невірний пароль `wrong_pass_3` та натиснути «Log in».
7. Оцінити стан форми входу та текст сповіщення.

#### Actual result
Система відображає повідомлення «Invalid login, please try again» над формою входу. Поля «Username» та «Password» залишаються активними, блокування форми та таймер відліку 15 хвилин відсутні.

#### Expected result
Після 3-ї невдалої спроби введення пароля обліковий запис блокується на 15 хвилин із виведенням повідомлення: «Обліковий запис тимчасово заблоковано на 15 хвилин через перевищення ліміту спроб входу» згідно з вимогами F-10 та S-20.

#### Environment
- **URL demo:** `https://sandbox.moodledemo.net` (стан зрізу від 20.10.2026)
- **Браузер:** Google Chrome 129.0.6668.101 (Official Build, 64-bit)
- **ОС:** Windows 11 Pro (версія 23H2)
- **Обліковий запис:** `student` / `sandbox24`

#### Attachments
- `BUG-001-1.png` — форма входу після трьох невдалих спроб введення пароля без активації блокування.

### Bug ID: BUG-002
**Title:** Відновлення пароля: система розкриває відсутність облікового запису в базі замість нейтрального повідомлення (F-20)  
**Severity:** Major  
**Priority:** P2  
**Linked:** test case TC-004; requirement F-20  
**Reporter:** Олександр Пархоменко (Інженер з тестування)  
**Reviewer:** Олександр Панайотов (Скрам-майстер / Рецензент) | **Дата рецензування:** 22.10.2026 | **Статус:** Reviewed ✓  

#### Description
Вимога F-20 у виправленій SRS 1.1 регламентує захист від перебору логінів (user enumeration): «якщо запис не знайдено або формат email невалідний — показується нейтральне повідомлення: «Якщо обліковий запис існує, інструкції надіслано на вказану пошту» для запобігання перебору логінів».  
Фактично при спробі пошуку неіснуючого користувача за логіном `nonexistent_student_2026` застосунок виводить повідомлення «This username was not found in the database. Please try again.», що прямо підтверджує факт відсутності користувача в базі даних.  
*Обґрунтування Severity:* Рівень Major присвоєно через виникнення суттєвої вразливості безпеки (User Enumeration), яка дозволяє зловмисникам автоматизовано формувати списки валідних логінів викладачів і студентів ЗВО.  
*Обґрунтування Priority:* Пріоритет P2 встановлено через необхідність першочергового усунення розробниками безпекового дефекту перед промисловою експлуатацією.

#### Steps to reproduce
1. Відкрити браузер Google Chrome у новій вкладці.
2. Перейти за адресою сторінки відновлення пароля: `https://sandbox.moodledemo.net/login/forgot_password.php`.
3. У секції «Search by username» знайти текстове поле «Username».
4. Ввести неіснуючий логін `nonexistent_student_2026`.
5. Натиснути кнопку «Search».
6. Ознайомитися з текстом системного повідомлення на оновленій сторінці.

#### Actual result
Система повертає користувача на сторінку пошуку та виводить текст помилки: «This username was not found in the database. Please try again.».

#### Expected result
Система відображає нейтральне інформаційне повідомлення: «Якщо обліковий запис існує, інструкції надіслано на вказану пошту» без розкриття наявності чи відсутності логіна в системі (вимога F-20).

#### Environment
- **URL demo:** `https://sandbox.moodledemo.net` (стан зрізу від 20.10.2026)
- **Браузер:** Google Chrome 129.0.6668.101 (64-bit)
- **ОС:** Windows 11 Pro (23H2)
- **Обліковий запис:** без попереднього входу (анонімний запит)

#### Attachments
- `BUG-002-1.png` — екран форми відновлення з виведеним текстом про відсутність користувача в базі.
