### Bug ID: BUG-001
**Title:** Форма входу: після помилки фокус не переноситься в поле «Пароль» (F-10, GUI-20)  
**Severity:** Minor  
**Priority:** P3  
**Linked:** test case TC-02; requirement F-10, GUI-20  
**GitHub Issue:** #1  
**Reporter:** Пархоменко О. (Інженер з тестування)  
**Reviewer:** Панайотов О. (Скрам-майстер / Рецензент) | **Дата рецензування:** 22.10.2026 | **Статус:** Open  

#### Description
GUI-20 (SRS 1.1) вимагає, щоб після невдалого входу повідомлення було червоним блоком над полями, «Ім'я входу» зберігало значення, «Пароль» очищувався, а фокус переходив у поле «Пароль».

Фактично після натискання «Увійти» повідомлення і очищення пароля працюють, але фокус залишається на кнопці «Увійти»: користувач, який друкує новий пароль з клавіатури, не бачить введення і має додатково натиснути поле мишею.

*Обґрунтування Severity:* Severity Minor: автентифікація і повідомлення працюють, пошкоджено лише зручність повторної спроби.  
*Обґрунтування Priority:* Priority P3: дефект не блокує виконання жодного тест-кейса.

#### Steps to reproduce
1. Відкрити Google Chrome у новій сесії інкогніто.
2. Перейти на https://sandbox.moodledemo.net/login/index.php.
3. У поле «Ім'я входу» ввести student.
4. У поле «Пароль» ввести WrongPass_2026 і натиснути «Увійти».
5. Не натискаючи мишею, ввести з клавіатури символ x і перевірити, у якому полі з'явився символ.

#### Actual result
Показано червоний блок «Невірне ім'я користувача або пароль», поле «Ім'я входу» зберегло student, поле «Пароль» порожнє. Фокусна рамка залишилася на кнопці «Увійти»; символ x не потрапив у поле пароля.

#### Expected result
Після кроку 4 фокус перебуває в полі «Пароль»; символ, введений з клавіатури на кроці 5, з'являється саме в цьому полі (GUI-20).

#### Environment
- **Demo:** https://sandbox.moodledemo.net (стан зрізу 21.10.2026)
- **Браузер:** Google Chrome 130.0.6723.70 (64-bit)
- **ОС:** Windows 11 Pro 23H2 (22631.4317)
- **Обліковий запис:** без входу (анонімна сесія)

Після кроку 5 обліковий запис заблоковано на 15 хвилин, поля форми недоступні, показано повідомлення «Обліковий запис тимчасово заблоковано на 15 хвилин». Крок 6 відхиляється з тим самим повідомленням (F-10, S-20).

#### Description
F-20 (SRS 1.1, DEF-07) вимагає однакового нейтрального повідомлення для наявного і неіснуючого запису: «Якщо обліковий запис існує, інструкції надіслано на вказану пошту».

*Обґрунтування Severity:* Severity Major: розкриття наявності облікових записів є суттєвою вадою захисту, хоча основний сценарій відновлення працює.  
*Обґрунтування Priority:* Priority P3: дефект не блокує виконання тест-кейсів спринту.

#### Steps to reproduce
1. Відкрити Google Chrome у новій сесії.
2. Перейти на https://sandbox.moodledemo.net/login/forgot_password.php.
3. У полі «Ім'я входу» ввести not_existing_student_2026.
4. Натиснути кнопку «Пошук» і прочитати повідомлення.

#### Actual result
Показано «This username was not found in the database. Please try again.» — повідомлення підтверджує, що облікового запису не існує.

#### Expected result
Показано нейтральне повідомлення «Якщо обліковий запис існує, інструкції надіслано на вказану пошту» без підтвердження або заперечення наявності запису (F-20).
