## 1. Вступ та цілі тест-дизайну

Метою цього документа є формалізація та інженерне обґрунтування вибору тестових даних для проектування комплекту незалежних тест-кейсів за виправленою специфікацією вимог **SRS 1.1**.  
Тест-дизайн забезпечує максимальну повноту тестового покриття функціональних і нефункціональних вимог системи за мінімально необхідної кількості тестів за рахунок застосування трьох фундаментальних технік «чорної скриньки» (Black-Box Test Design Techniques):
1. **Еквівалентне розбиття (Equivalence Partitioning, EP)**;
2. **Аналіз граничних значень (Boundary Value Analysis, BVA, методика 4 точок: $a-1, a, b, b+1$)**;
3. **Таблиці прийняття рішень (Decision Table Testing, DT)**.

## 2. Техніка 1: Еквівалентне розбиття (Equivalence Partitioning)

Вхідні параметри кожної форми та методу бізнес-логіки розбито на класи еквівалентності: валідні (позитивні перевірки, де система обробляє дані штатно) та невалідні (негативні перевірки, де система має відхилити запит або повернути повідомлення про помилку).

## 3. Техніка 2: Аналіз граничних значень (Boundary Value Analysis — BVA)

Для всіх вимог із числовими діапазонами застосовано метод граничних значень за методикою 4 точок:
- **$a - 1$**: точка безпосередньо перед нижньою межею (невалідний клас);
- **$a$**: точна нижня межа (валідний клас);
- **$b$**: точна верхня межа (валідний клас);
- **$b + 1$**: точка безпосередньо за верхньою межею (невалідний клас).

### 3.1. BVA Таблиця 1: Обмеження розміру файлу завдання (GUI-30, ліміт: $(0; 20.00]$ МБ)
Крок дискретизації: 0.01 МБ. Нижня межа $a = 0.01$ МБ, верхня межа $b = 20.00$ МБ.

| Точка BVA | Значення | Очікуваний результат обробки | Статус валідності | Відповідний тест-кейс |
|:---:|:---:|:---|:---:|:---:|
| **$a - 1$** | **0.00 МБ** (0 байт) | Помилка: «Файл не може бути порожнім» | Невалідний | — |
| **$a$** | **0.01 МБ** (10 КБ) | Файл успішно завантажено, відображається у списку | Валідний | TC-11 |
| **$b - 1$** | **19.99 МБ** | Файл успішно завантажено, відображається у списку | Валідний | TC-13 |
| **$b$** | **20.00 МБ** | Файл успішно завантажено, відображається у списку | Валідний | TC-13 |
| **$b + 1$** | **20.01 МБ** | Помилка: «Перевищено максимальний розмір файлу 20 МБ» | Невалідний | TC-13 |

| **$a$** | **1 файл** | Успішне прикріплення 1 файлу, збереження дозволено | Валідний | TC-11 |

## 4. Техніка 3: Таблиці прийняття рішень (Decision Tables)

### 4.1. Таблиця рішень DT-01: Валідація умов самозарахування (BL-70, BL-80)
Метод `EnrollmentValidator.canEnroll(student, course, today, key)` перевіряє 4 булеві умови:
1. `C1 (Key)`: Кодове слово збігається з урахуванням регістру (`keyMatches`);
2. `C2 (Period)`: Поточна дата в межах періоду реєстрації ($start \le today \le end$) (`withinPeriod`);
3. `C3 (Capacity)`: Наявні вільні місця на курсі ($enrolled < capacity$) (`hasCapacity`);
4. `C4 (Prerequisite)`: Передумовний курс складено на бал $\ge 60.0$ (`prerequisiteMet`).

### 4.2. Таблиця рішень DT-02: Алгоритм часткового балу тесту (BL-50)
Формула для питання з кількома правильними відповідями:  
$Score = \max\left(0.0, \frac{\text{обрані правильні}}{\text{усі правильні}} - \frac{\text{обрані неправильні}}{\text{усі неправильні}}\right) \times \text{макс\_бал}$.

| Правило | Обрані правильні ($K_{cor}$) | Обрані неправильні ($K_{inc}$) | Розрахунок формули | Підсумковий бал | Примітка та статус | Відповідний TC |
|:---:|:---:|:---:|:---:|:---:|:---|:---:|
| **R1** | Всі правильні ($N_{cor}$) | 0 | $1.0 - 0.0 = 1.0$ | **1.0 бал** | Ідеальна повна відповідь | **TC-18** |
| **R2** | Половина правильних | 0 | $0.5 - 0.0 = 0.5$ | **0.5 бала** | Частковий позитивний бал | **TC-21** |
| **R3** | Половина правильних | 1 неправильна ($1/N_{inc} = 0.5$) | $0.5 - 0.5 = 0.0$ | **0.0 балів** | Штраф нівелює бал | **TC-21** |
| **R4** | 0 | Всі неправильні | $0.0 - 1.0 = -1.0$ | **0.0 балів** | Захист від від'ємного балу ($\min 0.0$) | **TC-21** |
| **R5** | Жодної (`selected == null` або `""`) | 0 | 0.0 | **0.0 балів** | Відповідь не надана | **TC-20** |
| **R6** | Варіант не з множини `options` | — | — | `IllegalArgumentException` | Невалідна опція | JUnit 5 (Спринт 4) |
