## 1. Вступ

### 1.1 Призначення
Документ визначає вимоги до системи дистанційного навчання «ЕдуПортал» (далі — Система) версії 1.1 і є основою для проєктування тест-кейсів (Спринт 3), автоматизації тестування бізнес-логіки (Спринт 4) та побудови матриці простежуваності «вимоги × тест-кейси × дефекти» (Спринт 5). Читачі — тест-аналітики, інженери з тестування, керівник тестування, розробники та представник замовника.

### 1.2 Обсяг
«ЕдуПортал» — вебзастосунок класу LMS для закладів вищої та фахової передвищої освіти: курси з розділами й ресурсами, завдання зі здачею файлів або онлайн-тексту, тестування знань, форуми, журнал оцінок, самозарахування за кодовим словом, особистий профіль, календар подій. Версія 1.1 охоплює функції поточної версії продукту (їх представляє демонстраційний стенд, п. 2.2) та функціонал підсистеми «Журнал оцінок», бізнес-логіку якої винесено в модуль Java (розділ 5): зважений підсумок, конвертація у шкалу ECTS, штрафні санкції за запізнення, алгоритми оцінювання тестувань, валідація умов зарахування. Рейтинг групи до обсягу версій 1.0 та 1.1 не входить (заплановано на наступні релізи).

### 1.3 Терміни і скорочення

| Термін | Означення |
| :--- | :--- |
| **LMS (Learning Management System)** | Система керування навчанням — вебзастосунок для розміщення навчальних матеріалів, контролю знань та обліку успішності студентів. |
| **Курс** | Базова одиниця навчання: повна назва, коротка назва, категорія, календарні дати, розділи (секції) з навчальними ресурсами та діяльностями, перелік учасників. |
| **Діяльність (activity)** | Інтерактивний навчальний елемент курсу: завдання (assignment), тест (quiz), форум (forum). |
| **Самозарахування (self-enrolment)** | Спосіб зарахування, за якого студент самостійно реєструється на курс, увівши встановлене викладачем кодове слово. |
| **Кодове слово (enrolment key)** | Секретний символьний рядок, який викладач або менеджер задає для самозарахування студентів на курс. |
| **Елемент оцінювання (grade item)** | Рядок електронного журналу оцінок із заданим максимальним балом та ваговим коефіцієнтом у підсумковій оцінці курсу. |
| **Шкала ECTS** | Європейська кредитно-трансферна система: літерна шкала оцінювання (A, B, C, D, E, Fx, F), у яку конвертується числовий 100-бальний підсумок курсу за строгими напіввідкритими інтервалами (BL-20). |
| **Спроба (attempt)** | Одне проходження тесту користувачем від натискання кнопки «Спроба тесту» до фінального надсилання відповідей («Надіслати все і завершити»). |

### 2.2 Середовище функціонування
Система є вебзастосунком, оптимізованим для роботи в актуальних версіях браузерів Google Chrome та Mozilla Firefox; базовий інтерфейс системи функціонує за замовчуванням за українським мовним пакетом із можливістю перемикання на англійську мову. Демонстраційне середовище розгорнуто на базі Moodle LMS [3]; тестові облікові записи: `admin`, `manager`, `teacher`, `student` з паролем `sandbox24`.  
Модуль бізнес-логіки [4] розроблено мовою Java 17 (Maven), без сторонніх залежностей.

### 2.3 Обмеження і припущення
1. Демонстраційний стенд [3] автоматично скидається до початкового стану щогодини: створені курси, завдання та здані відповіді видаляються. Тестові набори даних генеруються заново на початку кожного сеансу тестування. Тест-кейси мають бути незалежними один від одного.
2. Після скидання середовища наявні два базові курси («My first course», «My second course», закріплені за «Teacher Terri»). Тестові завдання, тести, форуми та налаштування самозарахування створюються обліковим записом викладача або адміністратора безпосередньо перед прогоном тестів.
3. Демонстраційний сервер не надсилає реальні повідомлення електронної пошти: сценарії відновлення пароля (F-20) та зміни email у профілі (F-110) перевіряються до точки відправки поштового повідомлення або за системними логами подій.
4. Усі розрахунки балів, ваг та відсотків у модулі Java виконуються за типом `double` із математичним округленням за правилом `HALF_UP` (через `BigDecimal`); дати обробляються класом `java.time.LocalDate` без прив'язки до часових поясів.

## 5. Вимоги до бізнес-логіки модуля Java

Бізнес-логіку підсистеми оцінювання та валідації зарахування винесено в окремий незалежний модуль Java [4]: пакет `ua.kpi.tzyapz.eduportal`, що містить три сервісні класи та чотири DTO-записи (`record`). Бали та відсотки обробляються типом `double` із математичним заокругленням за правилом `HALF_UP` (через `BigDecimal`), дати — класом `java.time.LocalDate`, порушення вхідних передумов методів сигналізується винятком `IllegalArgumentException`.

### Програмні сигнатури DTO:
```java
public record GradeItem(String name, double score, double weight) {}
public record QuizQuestion(String id, Set<String> options, Set<String> correct) {}
public record Student(String id, Map<String, Double> completedCourses) {}
public record Course(String id, String enrolmentKey, LocalDate enrolStart, LocalDate enrolEnd, 
                     int capacity, int enrolled, String prerequisiteId) {}
```

### Специфікація бізнес-методів:

| ID | Формулювання вимоги до алгоритму | Пріоритет |
| :--- | :--- | :---: |
| **BL-10** | **Розрахунок зваженого балу:** `GradeCalculator.weightedTotal(List<GradeItem> items)`: кожен елемент списку повинен мати бал у межах `0.0..100.0` та вагу у відсотках. Сума ваг усіх елементів списку повинна дорівнювати рівно `100.0` (допускається похибка обчислень з плаваючою крапкою не більше `0.0001`), інакше генерується виняток `IllegalArgumentException`. Порожній або `null`-список, значення балу поза діапазоном `0.0..100.0` або від'ємна вага елемента — генерують виняток. Підсумок обчислюється за формулою: $Total = \sum (Score_i 	imes Weight_i) / 100.0$, результат заокруглюється до 2 знаків після коми за правилом `HALF_UP`. | High |
| **BL-20** | **Конвертація у шкалу ECTS:** `GradeCalculator.ectsLetter(double total)`: переводить числовий підсумок у літерний еквівалент ECTS за строгими неперервними напіввідкритими інтервалами: <br>• **A**: $95.00 \le total \le 100.00$ <br>• **B**: $85.00 \le total < 95.00$ <br>• **C**: $75.00 \le total < 85.00$ <br>• **D**: $65.00 \le total < 75.00$ <br>• **E**: $60.00 \le total < 65.00$ <br>• **Fx**: $35.00 \le total < 60.00$ <br>• **F**: $0.00 \le total < 35.00$ <br>Значення $total < 0.00$ або $total > 100.00$ — генерує виняток `IllegalArgumentException` *(DEF-04)*. | High |
| **BL-30** | **Розрахунок штрафу за запізнення:** `GradeCalculator.latePenalty(double score, int daysLate)`: нараховує штраф у розмірі -10 % від початкового балу за кожен повний день прострочення здачі роботи (`daysLate`), але не більше ніж -50 % загалом: $Penalty = \min(daysLate 	imes 10.0, 50.0)$; $Result = score 	imes (1.0 - Penalty / 100.0)$. При $daysLate = 0$ бал повертається без змін. Результат заокруглюється до 2 знаків після коми (`HALF_UP`). Значення $daysLate < 0$ або $score$ поза діапазоном `0.0..100.0` — генерують виняток `IllegalArgumentException`. | High |
| **BL-40** | **Оцінювання питання з однією правильною відповіддю:** `QuizScorer.questionScore(QuizQuestion question, Set<String> selected)`: якщо обрано саме правильний варіант і лише його — повертається `1.0` бал, інакше `0.0`. Якщо відповідь не надана (`selected == null` або порожня множина) — повертається `0.0` балів. Якщо обраний варіант відсутній у множині варіантів питання `options` — генерується виняток `IllegalArgumentException`. | High |
| **BL-50** | **Оцінювання питання з кількома правильними відповідями:** `QuizScorer.questionScore(QuizQuestion question, Set<String> selected)`: якщо `selected == null` або порожня множина — повертається `0.0` балів. Якщо `question == null`, або множина `options` порожня, або множина `correct` порожня — генерується `IllegalArgumentException`. Якщо `selected` містить варіант, відсутній у `options` — генерується `IllegalArgumentException`. Частковий бал обчислюється як: $Score = (	ext{обрані правильні} / 	ext{усі правильні}) - (	ext{обрані неправильні} / 	ext{усі неправильні})$; якщо неправильних варіантів у питанні немає, друга частка приймається рівною `0.0`. Якщо отримане значення $Score < 0.0$, результат прирівнюється до `0.0`. Максимальний бал за питання — `1.0` *(DEF-08)*. | High |
| **BL-60** | **Підсумкова оцінка спроби тесту:** `QuizScorer.score(Map<String, Set<String>> answers, List<QuizQuestion> key)`: обчислює результат спроби у відсотках за формулою: $Result = (\sum Score_i / N_{	ext{questions}}) 	imes 100.0$, де $N_{	ext{questions}}$ — загальна кількість питань у ключі тесту `key`. Результат заокруглюється до 1 знака після коми (`HALF_UP`). Якщо передано порожній ключ тесту або `key == null` — генерується `IllegalArgumentException`. | High |
| **BL-70** | **Комплексна валідація зарахування:** `EnrollmentValidator.canEnroll(Student student, Course course, LocalDate today, String key)` повертає `true` тоді і тільки тоді, коли одночасно виконано всі 4 передумови: <br>1. Кодове слово точно збігається з кодовим словом курсу (`c.enrolmentKey()`), з урахуванням регістру (`keyMatches`); <br>2. Дата `today` перебуває в межах періоду самозарахування: $enrolStart \le today \le enrolEnd$ включно (`withinPeriod`); <br>3. На курсі є вільні місця: поточна кількість зарахованих менша за місткість $enrolled < capacity$ (`hasCapacity`); <br>4. Передумовний курс (`prerequisiteId`), якщо він заданий, успішно складений студентом із підсумковим балом не менше ніж 60.0 балів (`prerequisiteMet`). | High |
| **BL-80** | **Формалізація порушень умов зарахування:** `EnrollmentValidator.violations(Student student, Course course, LocalDate today, String key)` повертає типізований список `List<String>`, що містить точні рядки помилок за кожною порушеною умовою: <br>• `"ERR_KEY: Невірне кодове слово"` — якщо кодове слово не збігається; <br>• `"ERR_PERIOD: Поза періодом зарахування"` — якщо поточна дата не входить у діапазон; <br>• `"ERR_CAPACITY: Ліміт місць вичерпано"` — якщо на курсі немає вільних місць; <br>• `"ERR_PREREQUISITE: Пререквізит не виконано (бал < 60)"` — якщо передумовний курс не складено. <br>Якщо всі умови виконано успішно, метод повертає порожній список `Collections.emptyList()` *(DEF-23)*. | Medium |
