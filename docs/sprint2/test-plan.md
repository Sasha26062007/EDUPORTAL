## 1. Загальний опис та об'єкт тестування

### 1.1. Мета планування тестування
Цей документ визначає комплексну стратегію, рівні, типи, методики, критерії та ресурсне забезпечення процесів забезпечення якості для вебплатформи дистанційного навчання **«ЕдуПортал»**. План складено на основі виправленої специфікації вимог **SRS 1.1** та замовлення на функціонал автоматизованого журналу оцінок (зважений підсумок, шкала ECTS, штрафи за запізнення, рейтинг групи та автоперевірка тестів).

### 1.2. Об'єкт тестування
- **Вебзастосунок:** SaaS-система дистанційного навчання «ЕдуПортал» (модульна архітектура, PHP 8.2, реляційна СУБД PostgreSQL 15, кешування сесій та черг Redis 7).
- **Ключові модулі бізнес-логіки:**
  - `GradeCalculator` — модуль зваженого обчислення підсумкового семестрового балу, трансляції у шкалу ECTS та розрахунку штрафів за прострочені дедлайни.
  - `QuizScorer` — модуль автоматизованої перевірки тестових завдань із підтримкою часткового балу для питань із множинним вибором без від'ємних результатів.
  - `EnrollmentValidator` — модуль валідації методів зарахування на курс, перевірки кодових слів і лімітів груп.
- **Тестове середовище (Demo-стенд):**
  - URL стенду: `https://sandbox.moodledemo.net` / локальний контур розгортання `http://localhost:8080/eduportal/`.
  - Тестові облікові записи: `admin` (Адміністратор), `manager` (Менеджер курсів), `teacher` (Викладач), `student` (Студент); спільний пароль: `sandbox24`.

## 4. Критерії процесів тестування

### 4.1. Критерії початку тестування (Entry Criteria)
1. Специфікація вимог SRS 1.1 затверджена після усунення знайдених дефектів.
2. Збірка застосунку успішно розгорнута на тестовому демо-стенді.
3. Smoke-тести (BVT) пройдені на 100% без блокуючих помилок.
4. Тестові облікові записи (`admin`, `manager`, `teacher`, `student`) створені та верифіковані.

### 4.2. Критерії призупинення та відновлення (Suspension & Resumption Criteria)
- **Призупинення:** виявлення дефекту рівня **Blocker/Critical**, який унеможливлює проходження базових сценаріїв (наприклад, крах модуля `GradeCalculator` або неможливість залогінитись).
- **Відновлення:** отримання хотфіксу від розробників, успішний повторний прогін Smoke-тестів та верифікація виправлення блокера.

### 4.3. Критерії завершення тестування (Exit Criteria / Definition of Done)
1. 100% запланованих тест-кейсів зафіксовані у журналі виконання.
2. $\ge 95\%$ тест-кейсів мають статус **passed**.
3. Відсутні відкриті дефекти рівнів **Blocker** та **Critical**.
4. Усі відомі дефекти рівня **Major** задокументовані у GitHub Issues та погоджені із замовником.
5. Матриця простежуваності покриває 100% вимог специфікації.

## 5. Середовище тестування та тестові дані

- **Апаратні вимоги сервера:** 4 vCPU, 8 GB RAM, SSD 50 GB.
- **Програмне забезпечення:** Ubuntu Linux 22.04 LTS, Nginx 1.24, PHP 8.2-FPM, PostgreSQL 15.4, Redis 7.0.
- **Клієнтські робочі станції:** Windows 11 / macOS 14 / Linux Ubuntu, монітори з роздільною здатністю 1920x1080 та 1366x768.
- **Тестові дані:**
  - Академічна група: «ФБ-44» (25 студентів).
  - Навчальний курс: «Технології забезпечення якості програмних засобів».
  - Елементи курсу: 4 практичні лабораторні (сумарна вага 40%), 2 модульні тести (вага 40%), активність на заняттях (вага 20%).
