## 3. Затвердження Плану тестування (`test-plan.md`) та стратегія пріоритезації

План тестування, розроблений Інженером з тестування (Володимиром Костенком), **ЗАТВЕРДЖЕНО** з наступними обов'язковими параметрами:

1. **Рівні тестування (7 рівнів — 100% покриття):**
   - Рівень 1: Модульне тестування (Unit Testing) — JUnit 5, Mockito (модулі `GradeCalculator`, `QuizScorer`, `EnrollmentValidator`);
   - Рівень 2: Інтеграційне тестування (Integration Testing) — модульні та інтеграційні тести зв'язки звітів LMS та Java-модуля;
   - Рівень 3: Приймальне тестування до початку тестування (Smoke / Build Verification Testing) — санітарний прогін ключових сценаріїв життєвого циклу;
   - Рівень 4: Системне тестування (System Testing) — наскрізні сценарії для всіх підтримуваних ролей за специфікацією SRS 1.1;
   - Рівень 5: Альфа-тестування (Alpha Testing) — внутрішня команда QA та розробники у закритому контурі Staging;
   - Рівень 6: Бета-тестування (Beta Testing) — пілотна група з викладачів та студентів групи ФБ-44;
   - Рівень 7: Приймальне замовником (User Acceptance Testing / UAT) — перевірка критеріїв замовником перед прийманням спринту.

2. **Типи тестування (усі 24 типи за §4.12: 22 застосовних + 2 незастосовних з обґрунтуванням):**
   - Норматив для 5 осіб ($\ge 15$ типів) повністю перевиконано (включено всі 24 типи §4.12).
   - Для кожного типу сформульовано унікальні, специфічні для «ЕдуПортал» поля **«Ціль»** та **«Опис»** з прив'язкою до тестових акаунтів (`teacher`, `student`, `manager`, `admin`) та пароля `sandbox24`.

3. **Матриця стратегічних пріоритетів тестування продукту:**

| Пріоритет | Компоненти та функціонал | Обґрунтування пріоритету Керівником | Рівні та типи тестування |
|:---:|:---|:---|:---|
| **P0 (Blocker / Critical)** | • Розрахунок оцінок і ECTS (`GradeCalculator`)<br>• Таймер та автооцінювання тесту (`QuizScorer`)<br>• Аутентифікація, безпека сесій та розмежування прав | Помилка в оцінці або витік персональних даних руйнує довіру до платформи та унеможливлює академічний процес. | Unit, Integration, Smoke, System;<br>Functional, Security, Boundary, Exception |
| **P1 (High)** | • Механізм самозарахування (`EnrollmentValidator`)<br>• Завантаження файлів практичних робіт (до 20 МБ)<br>• Навантаження при масовому тестуванні (200 юзерів) | Збій під час масового складання іспиту або втрата файлу студента блокує роботу сесії. | System, Stress, Load, Concurrency, Usability |
| **P2 (Medium / Low)** | • Пошук курсів та пагінація каталогу<br>• Локалізація інтерфейсу (укр/англ)<br>• Адаптивне відображення мобільної версії Web UI | Функціонал важливий для комфорту, але не призводить до втрати академічних даних. | GUI, Compatibility, Internationalization |
