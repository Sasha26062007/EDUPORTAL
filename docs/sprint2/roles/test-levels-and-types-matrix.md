## 1. Архітектурне зіставлення: Рівні тестування $\times$ Компоненти системи

Матриця визначає глибину перевірки кожного системного компонента на відповідних рівнях тестової піраміди:

| Рівень тестування | Модуль `GradeCalculator` | Модуль `QuizScorer` | Модуль `EnrollmentValidator` | Web UI (Клієнтська частина) | REST API & Сервісний шар | СУБД PostgreSQL 15 & Redis 7 |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|
| **1. Модульне (Unit)** | 🟢 Повне покриття (100% публічних методів, граничні бали, ECTS, штрафи) | 🟢 Повне покриття (алгоритм часткового балу, zero division, від'ємні оцінки) | 🟢 Повне покриття (кодові слова, перевірка лімітів місць, пререквізити) | ⚪ Не застосовується (UI тестується на вищих рівнях) | 🟡 Юніт-тести валідаторів DTO та контролерів | ⚪ Моки та заглушки (Mockito) |
| **2. Інтеграційне (Integration)** | 🟢 Збереження розрахованих сум у таблицю `mdl_grade_grades` | 🟢 Запис бланка відповідей і виклик обчислення оцінки | 🟢 Транзакційне зарахування та оновлення статусу в БД | 🟡 Валідація зв'язку Frontend $\leftrightarrow$ REST API | 🟢 Ендпоінти `/api/v1/grades`, `/api/v1/quiz/submit` | 🟢 Testcontainers PostgreSQL, інвалідація кешу Redis |
| **3. Приймальне до тестування (Smoke)** | 🟡 Базовий розрахунок 1 тестового журналу | 🟡 Проходження 1 простого тестового питання | 🟡 Зарахування 1 тестового студента | 🟢 Логін під 4 ролями, завантаження Dashboard | 🟢 Статус 200 на базових маршрутах API | 🟢 Перевірка з'єднання пулу з'єднань БД |
| **4. Системне (System)** | 🟢 Наскрізні сценарії журналу (US-01, US-02, US-04, US-05, US-06) | 🟢 Наскрізні сценарії тестування (US-10) з таймером | 🟢 Наскрізні сценарії каталогу курсів та самозарахування | 🟢 Повне функціональне та GUI тестування | 🟢 Повна верифікація контрактів API | 🟢 Цілісність даних при E2E сценаріях |
| **5. Альфа-тестування (Alpha)** | 🟢 Дослідницьке тестування екстремальних конфігурацій ваг | 🟢 Переривання сесії під час збереження відповідей | 🟢 Одночасне самозарахування понад ліміт | 🟢 Перевірка ергономіки та кросбраузерності командою | 🟢 Тестування безпеки (IDOR, XSS, CSRF) | 🟢 Моніторинг витоків пам'яті та довгих блокувань |
| **6. Бета-тестування (Beta)** | 🟢 Реальні семестрові відомості пілотних викладачів | 🟢 Проходження контрольних робіт 2 реальними групами | 🟢 Масове самозарахування студентів коледжу | 🟢 Оцінка зручності кінцевими користувачами (SUS) | 🟢 Моніторинг продуктивності на реальному трафіку | 🟢 Логування помилок Sentry / Grafana |
| **7. Приймальне замовником (Acceptance)** | 🟢 Демонстрація розрахунку ECTS та штрафів викладачу | 🟢 Демонстрація нарахування часткового балу | 🟢 Демонстрація роботи з кодовим словом | 🟢 Демонстрація адаптивності та фільтрації рейтингу | ⚪ Не демонструється прямо (приховано за UI) | ⚪ Перевірка підсумкових експортів XLSX/CSV |

## 2. Матриця розподілу 18 типів тестування за пріоритетами та артефактами

| № | Тип тестування | Категорія (ISO 25010) | Застосовність | Пріоритет | Ключові техніки тест-дизайну | Очікуваний результат / Артефакт |
|:---:|:---|:---|:---:|:---:|:---|:---|
| **1** | **Функціональне** | Functional Suitability | Так | **1** | Класи еквівалентності, таблиці рішень | Покриття 100% вимог SRS 1.1 та User Stories US-01..US-12. |
| **2** | **Граничні значення** | Functional Correctness | Так | **1** | Аналіз граничних значень (BVA: 2-point, 3-point) | Відсутність дефектів "off-by-one" на шкалі ECTS (59.99/60.00, 89.99/90.00). |
| **3** | **Регресійне** | Reliability / Maintainability | Так | **1** | Retest-all, selective regression | 100% проходження автотестів після багфіксів у версії v2. |
| **4** | **GUI / Інтерфейс** | Usability / UI | Так | **2** | Чек-листи перевірки верстки, евристики Нільсена | Валідація форм, коректність підсвічування групи ризику, відсутність visual bugs. |
| **5** | **Безпека & Доступ** | Security | Так | **2** | Fuzzing, Privilege Escalation, OWASP Top 10 | Ізоляція прав: студент не має доступу до чужих оцінок (IDOR-safe). |
| **6** | **API / Вебсервіси** | Compatibility / Interface | Так | **2** | Schema validation, Status code mapping | 100% валідність DTO відповідей, коректні 4xx коди помилок. |
| **7** | **Бази даних & ACID** | Data Integrity | Так | **2** | Транзакційний аналіз, concurrency test | Узгодженість журналу при паралельних транзакціях без deadlock. |
| **8** | **Надійність & Recovery** | Reliability | Так | **2** | Fault injection, network loss simulation | Збереження проміжних відповідей тесту при обриві зв'язку. |
| **9** | **Навантажувальне** | Performance Efficiency | Так | **3** | Load profile: 500 concurrent users | Час відгуку сервісу розрахунку $\le 2.0$ с при 500 активних сесіях. |
| **10** | **Кросбраузерне** | Portability | Так | **3** | Cross-platform compatibility matrix | Ідентична працездатність у Chrome, Firefox, Edge, Safari. |
| **11** | **Локалізація & UTF-8** | Usability / Cultural | Так | **3** | Character encoding testing | Бездоганне відображення кирилиці (і, ї, є, ґ) та експорт у CSV без кракозябр. |
| **12** | **Юзабіліті (UX/SUS)** | Usability | Так | **3** | Usability testing sessions, SUS survey | Оцінка за шкалою SUS $\ge 75$ балів («Добре» / «Зручно»). |
| **13** | **Стрес-тестування** | Reliability / Robustness | Так | **4** | Spike testing, resource exhaustion | Коректна обробка перевантаження через черги Redis без збою БД. |
| **14** | **Доступність (a11y)** | Accessibility | Так | **4** | WCAG 2.1 AA audit, axe-core scans | Повна доступність навігації з клавіатури, ARIA-лейбли для скрінрідерів. |
| **15** | **Об'ємне (Volume)** | Performance Efficiency | Так | **4** | High volume database queries (1M+ rows) | Швидкодія вибірки журналу групи $\le 1.5$ с при 1 000 000 записів у БД. |
| **16** | **Конфігураційне** | Compatibility | Так | **4** | Multi-environment Docker execution | Стабільність роботи на PHP 8.1 / 8.2 та різних лімітах RAM. |
| **17** | **Інсталяційне** | Portability | **Ні** | — | — | *Незастосовне: SaaS хмара, користувач не встановлює клієнтське ПЗ.* |
| **18** | **Мобільне нативне** | Platform Specific | **Ні** | — | — | *Незастосовне: відсутній окремий .apk/.ipa, тільки адаптивний веб.* |

## 3. Матриця простежуваності «Вимоги SRS 1.1 $\rightarrow$ Типи та рівні тестування»

| ID вимоги | Короткий зміст вимоги | Рівні тестування | Ключові типи тестування |
|:---|:---|:---|:---|
| **F-10..F-20** | Авторизація, захист від брутфорсу, відновлення доступу | Smoke, System, Alpha | Функціональне, Безпека, Граничні значення, GUI |
| **F-30..F-50** | Каталог курсів, самозарахування за кодовим словом, ліміти | System, Integration | Функціональне, API, Бази даних, Навантажувальне |
| **F-60..F-80** | Журнал оцінок, штрафи за запізнення, налаштування ваг | Unit, Integration, System | Функціональне, Граничні значення, Регресійне, Локалізація |
| **F-90..F-120** | Форуми, модерація, експорт журналу у XLSX/CSV | System, Alpha, UAT | Функціональне, Локалізація (UTF-8), Юзабіліті, a11y |
| **BL-10..BL-30** | Модуль `GradeCalculator`: ECTS (A..F), зважений бал, штраф | Unit, Integration | Функціональне, Граничні значення (BVA), Регресійне |
| **BL-40..BL-60** | Модуль `QuizScorer`: частковий бал, захист від від'ємного | Unit, Integration | Функціональне, Граничні значення, Надійність |
| **BL-70..BL-90** | Модуль `EnrollmentValidator`: кодове слово, пререквізити | Unit, Integration | Функціональне, Граничні значення, API |
| **P-10..P-30** | Продуктивність (200..500 користувачів, час відповіді $\le 2$ с) | System, Alpha | Навантажувальне, Стрес, Об'ємне |
| **S-10..S-40** | Безпека сесій, CSRF, XSS, хешування паролів bcrypt | Integration, System | Безпека & Доступ, API |
| **U-10..U-30** | Доступність інтерфейсу, навігація клавіатурою, WCAG AA | System, Beta | GUI, Юзабіліті, Доступність (a11y), Кросбраузерне |
