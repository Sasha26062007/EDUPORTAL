## 1. Паспорт ролі та закріплені інженерні задачі

У Спринті 4 наша команда перейшла до створення повноцінного автоматизованого регресійного тестового комплексу: написання модульних тестів JUnit 5 для бізнес-логіки продукту `ua.kpi.tzyapz.eduportal` (версія v1), розробки UI-сценаріїв для Selenium WebDriver 4 та фіксації закладених дефектів.

### Інженерні задачі, виконані Керівником тестування (Володимир Костенко):
1. **Декомпозиція замовлення та складання плану покриття BL-10..BL-80 (`docs/coverage-matrix.md`):**  
   Здійснено повний аналіз розділу 5 («Вимоги до бізнес-логіки») виправленої специфікації SRS 1.1 «ЕдуПортал». Розроблено наскрізну матрицю простежуваності, де кожне правило декомпозовано на класи еквівалентності (EP) та граничні значення (BVA: $N-1, N, N+1$), збалансовано розподілено тести між 5 членами команди та закріплено рецензентів.
2. **Розробка закріпленої частини юніт-тестів JUnit 5 (`GradeCalculatorTest.java`):**  
   Особисто розроблено та закомічено комплект із 4 обов'язкових та 2 додаткових тест-методів для правила **BL-10** (розрахунок зваженого підсумку `weightedTotal`): перевірка номінального розрахунку $\sum(Score_i \times Weight_i)/100$, округлення HALF_UP до 2 знаків після коми, валідація суми ваг ($=100.0$), діапазонів оцінок (0..100) та винятків `IllegalArgumentException` при некоректних даних і порожніх списках.
3. **Зведення головного `README.md` та протоколу запуску Surefire (`docs/surefire-summary.md`):**  
   Сформовано головну інструкцію репозиторію з точними інструкціями збірки без ручних правок (`mvn clean test`, `mvn test -DexcludedGroups=none`), структурою артефактів та таблицею авторів. Складено зведений протокол Surefire із зіставленням фактичних звітів `target/surefire-reports/` та аналізом падінь.
4. **Контроль нормативів спринта для 5 осіб:**  
   Забезпечено повне виконання нормативів:
   - Юніт-тести JUnit 5: **24 тести** (норматив $\ge 20$);
   - UI-сценарії WebDriver: **8 сценаріїв** (норматив $\ge 8$);
   - Знайдені закладені дефекти модуля: **6 дефектів** (норматив $\ge 5$);
   - Особистий внесок кожного учасника: **$\ge 4$ юніт-тести** (норматив $\ge 3$);
   - Selenium IDE: проєкт `eduportal.side` та експортні Java-чернетки готові.
5. **Підготовка та проведення живого Демо перед викладачем (`docs/demo-scenario.md`):**  
   Складено похвилинний сценарій 10-хвилинного живого показу: чистий запуск `mvn clean test` на очах викладача, демонстрація підсумку Surefire та «червоних» дефектів, запуск UI-тесту у видимому браузері та показ історії комітів.
6. **Оформлення закладених дефектів модуля (`docs/module-defects.md`):**  
   Зведено реєстр дефектів v1 (`MOD-BUG-001` — `MOD-BUG-006`) за стандартом Спринту 3 з обґрунтуванням Severity та Priority окремими реченнями.
7. **Підготовка команди до бліц-опитування (`docs/blitz-prep-sprint4.md`):**  
   Підготовлено глибокі академічні відповіді на всі 12 питань розділу 11 методичних вказівок.
