## 1. Загальний опис та методологія планування покриття

Відповідно до розділу 5.1 методичних вказівок Спринту 4, матриця простежуваності «BL-вимога $\rightarrow$ правило $\rightarrow$ тести» забезпечує повний контроль покриття модульного коду автотестами JUnit 5.

### Використані техніки тест-дизайну:
1. **Аналіз граничних значень (Boundary Value Analysis — BVA):**  
   Для кожного числового порогу $N$ (бали, дні, відсотки, кількість місць) перевіряються 3 точки:
   - $N - \Delta$ (безпосередньо перед межею);
   - $N$ (значення точно на межі діапазону);
   - $N + \Delta$ (безпосередньо після перетину межі).
2. **Еквівалентне розбиття (Equivalence Partitioning — EP):**  
   Розподіл вхідних даних на класи допустимих (валідна оцінка, правильний пароль) та недопустимих (від'ємні бали, порожні переліки, неіснуючі ідентифікатори).
3. **Негативне тестування та перевірка винятків (Exception Testing):**  
   Верифікація генерації `IllegalArgumentException` за допомогою `assertThrows` на некоректних аргументах.
